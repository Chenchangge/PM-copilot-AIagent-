# 复杂功能设计方法

## 概述

复杂功能设计需要同时处理多角色、多状态、多规则、多入口和异常情况，不能只依赖页面设计。

## 定义

复杂功能通常包含较多业务实体、状态、角色、规则和流程，需要通过结构化建模降低设计遗漏。

## 核心内容

可以按照以下顺序：
业务目标
→ 角色
→ 核心对象
→ 对象状态
→ 操作
→ 规则
→ 权限
→ 流程
→ 异常
→ 数据
例如企业审批：
角色：
发起人
审批人
抄送人
管理员
状态：
草稿
待审批
审批中
已通过
已拒绝
已撤回
操作：
提交
审批
驳回
撤回
转交
规则：
谁可以操作
什么状态可以操作
操作后状态如何变化
是否需要通知
是否可以再次编辑
对于复杂系统，可以使用状态机、权限矩阵、流程图、实体关系等方式辅助设计。

## 常见场景

- 企业SaaS
- 审批系统
- 订单系统
- AI Agent
- 项目管理系统

## 产品经理关注点

- 复杂功能设计最容易遗漏“状态 + 权限 + 异常”的组合。

## 常见误区

- 复杂功能就是页面多
- 复杂功能只能靠PRD解决
- 只画主流程就够了
- 状态和权限可以由开发自行决定
