# 状态设计

## 概述

状态设计是产品设计中经常被忽略但直接影响可用性的部分，需要覆盖数据、网络、权限和系统处理过程中的不同状态。

## 定义

状态设计描述产品在不同条件下向用户展示什么内容、允许什么操作以及如何恢复。

## 核心内容

常见状态包括：
初始状态
正常状态
加载状态
空状态
成功状态
错误状态
网络异常
权限不足
数据不存在
处理中
禁用状态
部分成功
超时
重试
例如 AI 问答：
用户提交问题
→ 请求中
→ AI生成
→ 成功显示回答
但还可能出现：
请求超时
→ 提示原因
→ 提供重试
模型不可用
→ 提示当前服务异常
→ 提供切换模型或稍后重试
没有检索到知识
→ 不应该假装生成确定答案
→ 提示当前知识库没有找到相关内容

## 常见场景

- AI产品
- 网络请求
- 文件上传
- 数据列表
- 权限系统
- 支付系统

## 产品经理关注点

- 一个完整产品方案不能只描述“正常情况下怎么走”。

## 常见误区

- 空状态就是没有数据
- Loading只需要转圈
- Error只需要弹Toast
- 异常状态属于开发实现，不属于产品设计
