# 用户场景与任务建模

## 概述

用户场景描述用户在什么情况下、为了什么目标使用产品；任务则描述用户需要完成的具体行为。

## 定义

用户场景通常包含用户、环境、触发事件、目标和约束；用户任务则进一步描述用户为了达成目标需要完成的操作。

## 核心内容

可以使用以下结构分析：
Who → Context → Trigger → Goal → Task → Constraint
例如：
用户：准备产品经理面试的应届生
场景：晚上临时准备第二天面试
触发：发现自己对 RAG 知识不熟
目标：快速掌握核心知识
任务：
查找 RAG 基础知识
阅读核心内容
回答相关问题
发现薄弱点
继续学习
场景建模能够帮助产品经理避免直接从“功能列表”开始设计。

## 常见场景

- 新功能设计
- 用户流程设计
- 移动端任务设计
- AI助手设计
- 复杂业务系统设计

## 产品经理关注点

- 设计功能之前先理解用户在什么场景下完成什么任务。

## 常见误区

- 场景等于用户画像
- 场景只需要描述用户身份
- 任务就是点击按钮
- 一个用户只有一个使用场景
