# 用户问题、痛点、需求与动机

## 概述

用户问题、痛点、需求和动机相关但并不完全相同。产品经理需要从用户表达的表层诉求继续分析背后的问题、目标和动机。

## 定义

可以采用以下实务上的区分：
问题：用户在完成任务过程中遇到的障碍。
痛点：对用户影响较明显、持续或具有较强负面感受的问题。
需求：用户希望解决问题或达成目标的诉求。
动机：驱动用户采取行为的原因。
这些概念在不同产品方法论中的边界并不完全统一，因此不应当把它们当成绝对标准术语。

## 核心内容

例如：
用户说：
“我希望有一个自动生成周报的功能。”
表面需求：
自动生成周报。
进一步分析：
问题：
每周整理数据和撰写周报耗时较长。
痛点：
周报占用了大量重复性时间，并且容易遗漏数据。
动机：
希望减少重复工作，把时间用于业务分析。
真正需要解决的问题可能是：
降低周报整理和汇总的时间成本，同时保证信息完整性。
最终解决方案未必一定是“AI 自动写周报”。

## 常见场景

- 用户提出具体功能
- 客服收集需求
- 销售反馈
- 产品反馈平台
- 用户访谈
- B 端客户定制需求

## 产品经理关注点

- 面试中经常考：
- 用户说“我要一个 XXX 功能”，你怎么办？
- 可以回答：
- 先确认用户是谁；
- 了解使用场景；
- 追问为什么需要；
- 找到实际问题；
- 判断问题价值和频率；
- 再判断解决方案。

## 常见误区

- 用户说出的功能就是需求。
- 所有痛点都值得解决。
- 用户自己提出的解决方案一定有效。
- 找到问题后就一定要做产品功能。
