# Tool Calling

## 定义

Tool Calling（工具调用 / Function Calling）是让大模型「调用外部工具或接口」的能力：模型判断用户的需求需要借助某个工具（搜索、查数据库、调用 API），于是按约定格式发起调用，把结果拿回来再继续回答。它是 AI Agent「会动手」的关键基础。

## 核心内容

产品经理理解 Tool Calling，重点是「它让模型从『只会说』变成『会做』」：

1. **解决什么问题**：模型有知识截止和幻觉问题，工具调用让它能「查实时信息、执行真实操作」
2. **工作方式**：模型输出「我要调用哪个工具、参数是什么」→ 系统执行 → 把结果回给模型 → 模型结合结果回答
3. **典型工具**：搜索、计算器、查询数据库、调用业务 API（下单、查订单、发通知）
4. **与 Agent 的关系**：Agent 的核心能力之一就是「会调用工具」，Tool Calling 是它的执行手段

对产品经理来说，Tool Calling 的价值是「让 AI 产品能真正帮用户完成动作，而不只是给建议」。

## 常见场景

- 面试被问「如何让 AI 助手查实时信息或帮用户下单」
- 设计「AI 客服 / AI 助手」类能「动手」的产品
- 与研发讨论「模型怎么调用我们的业务接口」

## 产品经理关注点

- 关注「工具的安全性」：让模型调用什么、调用前要不要确认，都要产品层面设计
- 关注「边界」：哪些操作能自动做，哪些必须用户确认（如支付、删除）
- 关注「体验」：工具调用中间态要给用户反馈（如「正在查询…」）
- 关注「兜底」：工具调用失败怎么办，要有错误处理

## 面试问题

### 1. Tool Calling 让 AI 产品多了什么能力？

### 2. 让 AI 能调用「下单」这类真实操作的接口，你会如何设计安全边界？

## 参考答案

### 问题 1

它让 AI 从「只能生成文字」变成「能执行真实动作」：查实时数据、调用业务接口、完成具体任务。比如一个客服助手，原来只能「告诉你大概怎么退」，有了工具调用就能「直接帮你查订单、发起退款」。这让 AI 产品的价值从「信息」升级到「办事」。

### 问题 2

我会把操作分级：查询类（查订单、查余额）可以自动执行；操作类（下单、退款、改地址）必须用户确认；高危类（支付、删除数据）要二次确认甚至人工介入。同时给模型「白名单」，只允许调用授权过的接口，参数也要校验。核心是「AI 可以提建议和发起，但关键动作的决定权在人」。
