# Prompt 工程

## 定义

Prompt（提示词）是给大模型输入的文字指令，用来引导它生成我们想要的输出。Prompt 工程就是设计和优化这些指令的方法，让模型输出更准确、更稳定、更符合预期。

## 核心内容

写好 Prompt 的常用技巧：

1. **角色设定**：告诉模型「你是谁」（如「你是一位资深产品经理」），框定回答视角
2. **明确任务**：说清楚要做什么（总结、分析、生成、翻译），越具体越好
3. **给上下文**：提供必要的背景信息，减少模型的「自由发挥」
4. **指定格式**：明确输出结构（如「用要点列出」「按 JSON 输出」）
5. **少样本示例**：给 1～2 个例子，让模型模仿格式和风格
6. **拆分复杂任务**：大任务拆成多步，逐步引导

产品经理不一定写代码，但要能写出「让模型按产品要求回答」的提示词。

## 常见场景

- 设计 AI 问答/面试功能时，定义「系统提示词」
- 面试被问「你怎么让 AI 按照产品要求来回答」
- 日常用 AI 工具时，优化自己的提问方式

## 产品经理关注点

- Prompt 是「产品规则的载体」：产品对 AI 的要求（语气、范围、格式）都要写进提示词
- 关注「稳定性」：好的 Prompt 要能稳定输出，而不是时而好时而坏
- 提示词要「可测试、可迭代」，像产品功能一样维护
- 敏感信息不能写进提示词，注意安全和合规

## 面试问题

### 1. 产品经理为什么需要懂 Prompt？

### 2. 如果 AI 产品的回答风格不符合你的产品定位，你会怎么调？

## 参考答案

### 问题 1

因为 Prompt 是把「产品需求」翻译成「模型行为」的桥梁。产品经理要能把「我们产品应该怎么回答、什么语气、什么边界」写成提示词，才能让 AI 输出符合产品定位。懂 Prompt 才能和研发对齐「AI 为什么这么答」，也能自己快速验证想法。

### 问题 2

我会先在系统提示词里明确「角色、语气、边界」，比如要求「用简洁专业的口吻、只回答产品相关的问题」。然后给几个示例让模型模仿，再用一批测试问题反复验证，看哪些场景跑偏就针对性地补规则。核心是把「产品想要的行为」一点点固化到提示词里，而不是让模型自由发挥。
