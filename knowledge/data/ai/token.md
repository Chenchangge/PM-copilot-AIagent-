# Token

## 定义

Token 是大模型处理文本时的最小计量单位，可以近似理解为「词或子词的一个片段」。模型按 Token 数量来理解输入、计算成本和限制长度，因此 Token 直接关系到产品的「成本和体验」。

## 核心内容

产品经理需要理解 Token 的几个要点：

1. **Token ≠ 字数**：一个中文词可能对应 1～2 个 Token，一段 1000 字的文本可能对应上千 Token
2. **输入和输出都算**：模型的成本 = 输入 Token + 输出 Token，两者都计费
3. **上下文窗口 = Token 上限**：模型一次能「读」的输入 + 「写」的输出总量是有限的，超出就放不下
4. **影响成本与延迟**：Token 越多，调用成本越高、响应越慢

对产品经理来说，Token 的核心意义是「要控制输入的长度和输出的长度，从而控制成本和体验」。

## 常见场景

- 设计 AI 产品时，评估「一次对话要花多少成本」
- 面试被问「AI 产品的成本从哪里来」
- 与研发讨论「为什么回答变慢 / 变贵了」

## 产品经理关注点

- Token 是 AI 产品的「隐形成本」，做功能前要估算
- 控制上下文长度：不是所有历史对话都要塞给模型，要设计「裁剪/摘要」策略
- 在「信息完整」和「成本控制」之间权衡：输入太长浪费钱，太短模型答不好
- 输出长度也要约束：让模型「简洁回答」能省钱

## 面试问题

### 1. 为什么 AI 产品经理需要理解 Token？

### 2. 一个 AI 对话产品，用户对话越来越长导致成本上升，你会怎么优化？

## 参考答案

### 问题 1

因为 Token 直接决定 AI 产品的「成本和体验」。理解了 Token，我才能估算一次对话要花多少钱、为什么响应会变慢、上下文能塞多少内容，从而在设计功能时控制成本、优化体验。不懂 Token，就没办法把 AI 产品做成「可持续经营」的产品。

### 问题 2

我会从「控制输入长度」和「控制输出长度」两方面入手：对长对话做「摘要 + 只保留最近几轮」的策略，避免把全部历史都发给模型；同时限制单次回答的长度、引导用户问更聚焦的问题。核心是「在信息足够和成本可控之间找平衡」，而不是无限制地把所有上下文都塞进去。
