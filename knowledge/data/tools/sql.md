# SQL

## 定义

SQL（Structured Query Language）是用于查询和操作数据库的语言。对产品经理来说，SQL 是「自己动手取数、验证想法」的能力，能减少对数据分析师的依赖，让决策更快。

## 核心内容

产品经理需要掌握的 SQL 通常不深，核心是「会查、会聚合、会筛」：

1. **查数据**：`SELECT` 从表里取数据
2. **筛选**：`WHERE` 按条件过滤
3. **聚合**：`GROUP BY` + `COUNT/SUM/AVG` 做统计
4. **排序与限制**：`ORDER BY`、`LIMIT` 看排名和 top 数据
5. **多表关联**：`JOIN` 把不同表的数据连起来

产品经理用 SQL 的目的不是「当工程师」，而是「能自己验证一个数据问题」，比如「某功能上线后使用率是多少」。

## 常见场景

- 面试被问「你会 SQL 吗，到什么程度」
- 需要快速查一个指标，又不想等数据同事排期
- 验证「某类用户的行为数据」

## 产品经理关注点

- SQL 是「取数验证」能力，不是「炫技」，够用就行
- 会自己查数，能大幅提升决策速度和独立性
- 查数前先想清楚「我要验证什么」，再写查询，避免「查了一堆没用」
- 数据口径要和数据团队对齐，避免「各查各的数对不上」

### 2. 如果你查的数据和数据分析师查的对不上，你会怎么办？

## 参考答案

### 问题 1

因为 SQL 能让我「自己验证想法」：想看看某个功能的使用率、某类用户的行为，我可以直接查，不用等数据同事排期。这不代表要替代数据分析师，而是「高频、简单的取数自己能做」，让决策更快、更独立。核心是「数据驱动」的落地能力。

### 问题 2

我会先核对「口径」：是不是统计时间、筛选条件、指标定义不一样（比如「活跃」的定义、是否去重）。很多时候数字对不上是口径不一致，而不是谁算错了。我会和数据同事对齐口径后再查，确保大家说的是同一个东西。
