# Golden Set（黄金评测集）

## 定义

Golden Set（黄金评测集）是从评测数据中精选出来、经过人工确认、质量较高、带有稳定参考答案或期望行为的一小批核心基准样本。它用于在离线评测中可靠地比较模型、Prompt 或 RAG 版本的好坏，是评测体系的「锚点」。

## 核心内容

### 1. Golden Set 与普通 Evaluation Dataset 的区别

`ai-evaluation-dataset`（评测数据集）是更大、更宽泛的概念，可以包含大量原始、噪声、未标注的样本。Golden Set 是它的一个**高质量子集**：样本数量更少，但每条都经过人工审核、有明确且稳定的期望输出，是「用来定好坏」的核心基准。简言之：**评测数据集是「材料库」，Golden Set 是「标准答案卷」**。

### 2. 为什么需要 Golden Set

如果每次都拿几百上千条未经确认的样本去比版本，噪声会淹没真实差异，也很难判断「这条答得好不好」。Golden Set 用少量高质量样本，快速、稳定、可解释地给出结论，适合在频繁的版本迭代中做回归和对比。

### 3. Golden Set 的组成

一条合格的 Golden Set 样本至少包含：

- **输入**：用户问题 / 任务 / 上下文
- **期望输出 / reference answer**：人工确认的标准答案或关键要素
- **评价标准 / rubric**：这条样本「好/坏」的判定规则
- **标签与元数据**：难度、场景、能力维度、风险等级等

### 4. 数据来源与人工审核

Golden Set 的来源通常包括真实高频用户问题、线上 bad case、边界案例等。样本进入 Golden Set 前必须经过**人工审核**，确认「参考答案正确、评价标准清晰、样本没有歧义」，这是它区别于普通数据集的关键。

### 5. 质量门槛

不是所有样本都能进 Golden Set。准入标准包括：答案是明确的或有公认判据的、问题是高频且有代表性的、期望行为是稳定的、不依赖「唯一措辞」就能判断对错。达不到门槛的样本留在普通数据集里，不进 Golden Set。

### 6. 覆盖面与版本管理

Golden Set 要**按维度覆盖**：既要有常见场景，也要有**边界案例**（异常输入、超长上下文、多轮追问）和**高风险案例**（涉及事实准确性、安全、合规的场景）。同时要像代码一样做**版本管理**：改一条样本或标准，就要有新版本，才能保证「同一版本对比」是公平的。

### 7. Golden Set 如何用于离线评测

把候选版本（新模型 / 新 Prompt / 新 RAG 配置）跑一遍 Golden Set，按每条样本的 rubric 打分，再汇总成整体指标。因为 Golden Set 样本稳定、标准明确，不同版本在同一套样本上的得分差异，才能反映真实的能力变化。

### 8. Golden Set 的局限

- **数据泄漏 / 过拟合风险**：如果 Golden Set 被模型训练数据见过，或者团队「针对 Golden Set 调参」，分数就会虚高，失去代表性
- **覆盖有限**：少量样本无法覆盖所有线上场景，只能代表「已纳入维度」的质量
- **静态 vs 动态**：用户问题会变，Golden Set 若长期不更新会「过期」

## 常见场景

- 每次模型 / Prompt / RAG 版本上线前，跑一遍 Golden Set 做回归对比
- 面试被问「你怎么保证 AI 产品改版后质量不退化」
- 从大量评测数据中挑选「最值得重点盯」的核心样本

## 产品经理关注点

- Golden Set 不是「越多越好」，关键是**每一条都确认过、标准清晰**，宁可小而准
- 要设计「覆盖面」：边界案例和高风险案例必须进，不能只挑「答得漂亮」的简单题
- 要警惕「针对 Golden Set 过拟合」，区分「真提升」和「刷分」
- 建立版本管理和更新机制，让 Golden Set 跟着产品场景演进

## 常见误区

- 把 Golden Set 当成「所有评测数据」或「只要量大就好」
- 样本没有经过人工审核就标为 Golden，导致「标准答案」本身不可信
- 只覆盖简单、常见场景，漏掉边界和高风险案例
- 忽视数据泄漏：拿训练集里的样本当评测集，分数失去意义
- 长期不更新，Golden Set 与实际用户问题脱节

## 案例

- 以「知识库问答产品」为例：团队从线上真实问题和人工标注数据里，挑出 100 条高频、有明确答案、覆盖「常见事实问答 / 边界歧义 / 高风险事实准确性」三类场景的问题，每条都人工写好参考要点和判定规则，组成 v1 版 Golden Set。之后每次改 Prompt 或换模型，都先在这 100 条上跑回归，只有关键指标不下降才允许上线，避免「改了一处、坏了全局」。当线上出现新的高频 bad case 时，再补进 Golden Set 并升级到 v1.1。
