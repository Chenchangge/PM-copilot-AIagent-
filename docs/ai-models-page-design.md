## 2. 页面整体结构

移动端优先，从上到下分为 5 个区块：

```
┌─────────────────────────────┐
│ ‹ 返回        AI 模型 / API     │  ← PageHeader（含返回）
├─────────────────────────────┤
│                              │
│  §1  我的模型                │  ← SectionTitle + 添加入口
│  ┌───────────────────────┐  │
│  │ DeepSeek        ✓已连接 │  │
│  │ deepseek-flash          │  │
│  │ ✓文本生成 ✓推理 …      │  │
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │ Gemini         ✕连接失败 │  │
│  │ …                     │  │
│  └───────────────────────┘  │
│  [+ 添加模型]               │  │
│                              │
│  §2  功能模型                │  │ ← 功能 → 模型绑定
│  ┌───────────────────────┐  │
│  │ 知识问答    DeepSeek >  │  │
│  │ 文本生成 + RAG         │  │
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │ 知识库 Embedding  未配置>│ │
│  │ Embedding             │  │
│  └───────────────────────┘  │
│                              │
│  §3  能力说明                │  │ ← 6 类能力解释
│                              │
└─────────────────────────────┘
```

**结构要点：**

- 单一纵向滚动，不分区 Tab，避免后台系统感
- 区块用 `SectionTitle` 分隔，间距沿用 `mt-8`
- 模型列表为 2～3 张轻量 `card`，不做大量卡片堆叠
- 「添加模型」用次级入口（虚线/描边按钮），不抢占主 CTA

沿用 Step 2 确立的体系，**不引入新视觉风格**：

## 4. 「我的模型」区域

### 4.1 列表项（ModelCard）

每个模型展示一行卡片，字段从左到右、上到下：

```
┌────────────────────────────────────────────┐
│ [厂商名]                     [状态徽标]     │
│ model 名称（等宽小字）                        │
│ ✓文本生成 ✓推理 ✓结构化输出 ✕图像生成 ?Embedding │
│                                  [编辑][测试] │
└────────────────────────────────────────────┘
```

| 字段 | 展示规则 |
| --- | --- |
| 厂商名称 | `text-sm font-medium text-gray-900`（如 DeepSeek / OpenAI / Claude / Gemini / 自定义） |
| Model 名称 | `text-xs text-gray-400` 等宽字体（如 `deepseek-flash`） |
| 配置状态 | 右上角徽标，见 4.2 |
| 支持能力摘要 | 一行徽标，最多展示前 3 项 + `…`，见第 7 章 |
| 编辑 | 文本按钮，进入编辑表单 |
| 测试连接 | 次级文本按钮，触发连通性测试 |

### 4.2 配置状态（ConnectionBadge）

| 状态 | 样式 | 文案 |
| --- | --- | --- |
| 已连接 | 绿底绿字（`bg-green-50 text-green-600`） | ✓ 已连接 |
| 连接失败 | 红底红字 | ✕ 连接失败 |
| 未测试 | 灰底灰字 | 未测试 |

> 状态只反映「最近一次测试/保存结果」，不实时探测。

### 4.3 空状态

无任何模型时，整个「我的模型」区块替换为 `EmptyState`：

- 标题：`还没有配置 AI 模型`
- 说明：`使用 AI 功能前，请先配置自己的模型 API。`
- 主按钮：`添加模型`

## 5. 「添加模型」流程

```
添加模型
   ↓
选择厂商（DeepSeek / OpenAI / Claude / Gemini / 其他兼容 OpenAI API）
   ↓
填写 API 信息（Base URL · API Key · Model · 能力只读展示）
   ↓
测试连接
   ↓
连接成功 / 连接失败（可返回修改后重试）
   ↓
保存（成功后回到列表，新模型出现在「我的模型」）
```

交互载体：**整页表单**（不用多步骤弹窗，移动端体验更稳）。厂商选择用 `ChoiceGroup`（5 个 pill），其余为表单字段。

**关键约束：**

- 「保存」与「测试连接」是两个独立动作：用户可先保存后测，也可先测后保存
- 测试失败**不阻止保存**，但保存时若「未测试/失败」，状态徽标显示对应状态并提示后续可再测
- 厂商预设只决定 Base URL 的自动填充与能力标签的默认值，**不调用任何厂商 SDK**

## 6. 模型配置字段

| 字段 | 必填 | 交互规则 |
| --- | --- | --- |
| 厂商 | 是 | `ChoiceGroup`，选择后触发 Base URL / 能力标签自动填充 |
| API Base URL | 否（部分厂商自动填充） | 预设厂商自动填充，允许修改；「其他」需手动填写 |
| API Key | 是 | 默认脱敏，见第 10 章 |
| Model | 是 | 手动填写；MVP 不做「从厂商 API 拉取模型列表」，留待后续 |
| 模型能力 | 只读 | 系统根据厂商预设决定，用户不可勾选，见第 7 章 |

### 6.1 Base URL 自动填充规则

| 厂商 | 默认 Base URL（示例，非实现） |
| --- | --- |
| DeepSeek | `https://api.deepseek.com` |
| OpenAI | `https://api.openai.com/v1` |
| Claude | `https://api.anthropic.com` |
| Gemini | `https://generativelanguage.googleapis.com` |
| 其他（OpenAI 兼容） | 空，需手动填写 |

> 自动填充后仍允许修改；上述值仅为设计示例，具体端点以后续技术方案为准。

## 7. 模型能力设计

### 7.1 能力清单（沿用 PRD 8.1）

1. 文本生成
2. 推理
3. 结构化输出
4. 多模态理解
5. 图像生成
6. Embedding

### 7.2 展示三态（CapabilityIcon）

| 态 | 图标 | 含义 |
| --- | --- | --- |
| 支持 | `✓`（绿） | 该模型支持此能力 |
| 不支持 | `✕`（灰） | 该模型不支持 |
| 未知 | `?`（灰/描边） | 未验证，系统未确定 |

### 7.3 核心原则：用户不可手动勾选

能力**不由用户勾选**，而由系统根据厂商/模型适配信息决定；UI 只做**只读展示**。本轮仅设计展示交互，不实现真实能力检测。

### 7.4 示例

**DeepSeek（示例默认能力标签）：**

```
✓ 文本生成   ✓ 推理   ✓ 结构化输出   ✕ 多模态理解   ✕ 图像生成   ? Embedding
```

> 以上为设计示例值，实际能力以厂商适配信息为准（技术实现阶段确定）。

## 8. 「功能模型」区域

### 8.1 功能列表（FunctionModelRow）

每一项展示：功能名称、所需能力、当前使用模型，右侧 chevron 进入选择。

| 功能 | 所需能力 | 当前使用模型 |
| --- | --- | --- |
| 知识问答 | 文本生成 + RAG | DeepSeek > |
| 模拟面试 | 推理 + 结构化输出 | DeepSeek > |
| 面试评价 | 推理 + 结构化输出 | 未配置 > |
| 产品设计辅助 | 根据功能需要 | Gemini > |
| 知识库 Embedding | Embedding | 未配置 > |

展示规则：

```
┌──────────────────────────────────────┐
│ 知识问答                    DeepSeek > │  ← 功能名 + 当前模型
│ 文本生成 + RAG                         │  ← 所需能力（辅助小字）
└──────────────────────────────────────┘
```

- 功能名 `text-sm font-medium text-gray-900`
- 所需能力 `text-xs text-gray-400`
- 当前模型 `text-sm text-brand-600`（有）/ `text-xs text-gray-400`（未配置）
- 点击整行 → 打开「选择模型」底部抽屉

## 9. 模型选择逻辑

### 9.1 载体

「选择模型」使用**底部抽屉（Bottom Sheet）**，从下方滑入，标题为「为「知识问答」选择模型」。

### 9.2 过滤规则

系统只展示**满足该功能能力要求**的模型：

```
用户选择功能
   ↓
系统读取该功能的 requiredCapabilities
   ↓
过滤已配置模型中「支持全部所需能力」的模型
   ↓
列表展示（含每项能力摘要）
```

**示例：** 为「知识库 Embedding」选择模型：

| 已配置模型 | 是否可选 | 原因 |
| --- | --- | --- |
| DeepSeek（✕ Embedding） | 不可选（置灰，标注「不支持 Embedding」） | 能力不满足 |
| Gemini（? Embedding） | 可选但标注「未验证」 | 未知视为可尝试 |

> `?`（未知）能力的模型**允许被选择**，但选择后给出提示「该能力未验证，建议先测试连接」。

### 9.3 空状态（无符合模型）

```
┌──────────────────────────────────────┐
│        （图标）                        │
│    暂无符合条件的模型                  │
│  当前没有支持 Embedding 的模型         │
│        [配置模型]                      │
└──────────────────────────────────────┘
```

- 标题：`暂无符合条件的模型`
- 说明：`当前没有支持 Embedding 的模型。`（能力名随功能动态）
- 按钮：`配置模型` → 关闭抽屉并打开「添加模型」表单，**不跳转到某个具体厂商**

## 10. 测试连接

### 10.1 四态

| 状态 | 表现 |
| --- | --- |
| 未测试 | 按钮「测试连接」为可用态 |
| 测试中 | 按钮 loading（转圈 + `测试中…`），禁用 |
| 测试成功 | 绿色 `✓ 连接成功`，可显示模型名称 + 响应时间（如 `235ms`） |
| 测试失败 | 红色 `✕ 连接失败` + 友好错误文案（见 10.2） |

### 10.2 错误提示（用户可理解，不暴露底层异常）

| 底层原因（示例） | 展示文案 |
| --- | --- |
| 401 / 密钥错误 | `API Key 无效，请检查配置。` |
| 网络不可达 / DNS 失败 | `无法连接模型服务，请检查 Base URL。` |
| 超时 | `连接超时，请稍后重试。` |
| 模型不存在 / 404 | `未找到该 Model，请检查 Model 名称。` |
| 其他未知错误 | `连接失败，请检查配置后重试。` |

> 禁止把堆栈信息（`ConnectionError … traceback`）展示给用户；错误提示**不包含** API Key 的任何片段。

## 11. API Key 安全交互

| 规则 | 设计 |
| --- | --- |
| 默认隐藏 | 列表与表单中 Key 均显示为 `••••••••••••abcd`（保留末 4 位） |
| 临时显示 | 表单内提供「👁 显示」切换，仅输入/编辑时可暂时明文，失焦或离开后恢复脱敏 |
| 保存后不可明文 | 保存成功后，列表/详情永不以明文展示 |
| 不进前端日志 | 交互设计明确 Key 不参与任何 `console` / 埋点输出 |
| 不出现在错误提示 | 所有报错文案不拼接 Key 片段 |
| 不进 Git | Key 属于用户运行时数据，不写入代码库 |
| 删除时清除 | 删除模型即删除其 Key，见第 12 章第 5 条 |

> 以上为**产品交互原则**；「Key 如何安全存储 / 加密」属后续**技术实现**范畴，本文档不展开。

## 12. 异常状态

### 12.1 没有配置任何模型

- 空状态：标题 `还没有配置 AI 模型`，说明 `使用 AI 功能前，请先配置自己的模型 API。`，按钮 `添加模型`

### 12.2 模型配置成功

- 「我的模型」正常显示列表项，状态徽标 `✓ 已连接`

### 12.3 API 测试失败

- 列表项徽标 `✕ 连接失败`，下方附 `修改` 入口 + 失败原因摘要（友好文案）

### 12.4 功能没有可用模型

- 「功能模型」该项显示 `未配置`；点击进入选择抽屉时，若过滤后为空，展示 9.3 的空状态与 `配置模型` 按钮

### 12.5 删除模型

- 触发：模型列表项「更多 / 删除」或编辑页底部「删除模型」
- 需二次确认，弹窗文案：
  - 标题：`删除「DeepSeek」？`
  - 说明：`删除后，使用该模型的功能需要重新选择模型。`
- 确认后删除模型配置并清除其 API Key

## 14. 数据模型（仅设计，非实现）

```ts
type ConnectionStatus = 'connected' | 'failed' | 'untested'
type Capability = 'text' | 'reasoning' | 'structured' | 'multimodal' | 'image' | 'embedding'
type CapabilityState = 'supported' | 'unsupported' | 'unknown'

interface ModelConfig {
  id: string
  vendor: 'deepseek' | 'openai' | 'claude' | 'gemini' | 'custom'
  displayName: string          // 展示名（默认厂商名，可编辑）
  baseUrl?: string             // 自定义端点，部分厂商自动填充
  apiKeyMasked: string         // 脱敏显示，永不明文
  model: string                // 实际调用的 model 标识
  capabilities: Record<Capability, CapabilityState>
  connectionStatus: ConnectionStatus
  lastTestedAt?: string
  responseTimeMs?: number
}

type AiFunctionId = 'qa' | 'interview' | 'evaluation' | 'product-design' | 'embedding'

interface AiFunctionBinding {
  id: AiFunctionId
  name: string                 // 知识问答 / 模拟面试 / 面试评价 / 产品设计辅助 / 知识库 Embedding
  requiredCapabilities: Capability[]
  boundModelId?: string        // 当前使用模型，未配置为空
}
```
