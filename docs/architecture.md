# 架构概览

> 产品需求见 [PRD.md](./PRD.md)；接口约定见 [api.md](./api.md)。

## 分层

```
┌─────────────────────────────────────────────────────┐
│  Frontend (Vue 3 + Vite + Tailwind)                 │
│  移动端优先，页面骨架 + Mock 数据占位               │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP (Axios / /api)
┌──────────────────────▼──────────────────────────────┐
│  Backend (FastAPI)                                  │
│  api/routes ── services ── db (SQLAlchemy + SQLite) │
└──────┬───────────────────────────────┬──────────────┘
       │                               │
┌──────▼──────────┐          ┌─────────▼──────────┐
│  DeepSeek API    │          │  RAG (Chroma/FAISS)│
│  (问答/面试/评价)│          │  knowledge/        │
└─────────────────┘          └────────────────────┘
```

## 关键决策

- **API Key 隔离**：`DEEPSEEK_API_KEY` 仅从后端环境变量读取，前端零接触。
- **RAG 位置**：知识检索在 `knowledge/` 目录承载，由后端 `services` 调用，索引与原始文档分离。
- **评价逻辑**：`evaluation/` 目录承载提示词与评分 schema，由后端服务加载，前端不实现评分逻辑。
- **移动端优先**：前端以 `max-width` 容器居中，390×844 / 375×812 优先，PC 下居中显示。

## 数据流（目标）

1. 用户学习 → 记录到 `learning-history`
2. 用户发起模拟面试 → 后端调用 DeepSeek 生成题目
3. 面试回答 → 后端调用评价服务（`evaluation/`）产出评分
4. 评价得到薄弱点 → 推荐学习路径
5. 回到学习，形成闭环
